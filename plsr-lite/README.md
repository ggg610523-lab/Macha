# plsr-lite

A from-scratch x86_64 Mach-O loader. It replaces the decompiled
`pulsar-appexec` pseudocode, which is not compilable (458 syntax errors in `main`
alone), with code that builds and runs. It is a working loader, not a dyld
clone.

    make
    ./tests/run.sh

Fixtures are generated by `tests/gen_machos.py`; no macOS toolchain is needed.

Implemented:
- thin and fat (universal) Mach-O, x86_64 slice selection
- load-command parsing with bounds checks; `__PAGEZERO` skipped
- image reservation, per-segment `MAP_FIXED` mapping, slide, deferred `initprot`
- `LC_MAIN` entry, `LC_UNIXTHREAD` x86_64 entry fallback
- `LC_LOAD_DYLIB` / weak / reexport / lazy / upward dylib list parsing
- classic `LC_DYLD_INFO[_ONLY]` rebase opcodes (all six forms)
- classic bind/lazy/weak opcodes (all eight forms, SLEB addends)
- chained fixups: import formats 1/2/3, uncompressed and zlib symbol pools,
  `DYLD_CHAINED_PTR_64` and `DYLD_CHAINED_PTR_64_OFFSET`
- export tries (including reexports) and `LC_SYMTAB` fallback
- dylib loading from disk: `@rpath`, `@loader_path`, `@executable_path`, and
  absolute install names mapped under a Pulsar runtime root; recursive closure,
  per-path dedup, weak dependencies
- runtime-root discovery from `/proc/self/exe`
  (`<bindir>/../lib/pulsarappexec`) with `$HOME/.local/share/pulsarappexec`
  fallback, plus `--runtime`
- `.app` bundles: `Contents/Info.plist` -> `CFBundleExecutable`, else first file
  in `Contents/MacOS`
- host libc shim table (write/read/close/exit/malloc/free/mem*/str*/printf/...)
- process stack (argc/argv/envp) and jump to entry
- Swift image registration in run mode: after rebasing, binding, and applying
  final segment protection, calls libswiftCore's type-metadata, protocol, and
  protocol-conformance registration over each image's `__swift5_types`,
  `__swift5_protos`, and `__swift5_proto` sections. `PLSR_SWIFT_REG_TRACE=1`
  logs the registered ranges. `--load` deliberately does not execute this.
- `--info <file>`: segments, entry, dylib list, fixup/import inventory without running
- `--load <file>`: load and fix up a full image closure without executing it
- `--stub-missing[=zero]`: bind unresolved imports to zero instead of failing
- `--image-map <file>`: install-name-to-path overrides, one `name path` per line

Verified: `tests/run.sh` = 17 passed, 0 failed. The suite covers chained
rebases and imports, classic binds, a dylib loaded from a runtime root, a
two-level dylib dependency with a classic bind inside the dylib, an `@rpath`
framework inside an `.app`, and a load-only pass over the real CotEditor
closure.

`--load --runtime pulsar-appexec/usr/lib/pulsar-appexec
app/CotEditor.app/Contents/MacOS/CotEditor` reports 84 images loaded, zero
missing, and zero fixup errors.  `libswiftQuickLookUI.dylib` is not shipped in
this runtime, but it is an optional dependency: it is reported as a stub and
is not counted as a missing required image.

Not implemented, so this cannot run CotEditor or any real macOS app: the
Objective-C runtime, AppKit/SwiftUI host entry points, and Metal translation.
The shipped `usr/lib/pulsar-appexec/bin/appexec` does all of that and already
runs CotEditor.app from this tree; `plsr-lite` covers the mapping, dependency,
fixup, and entry half of the same pipeline.
